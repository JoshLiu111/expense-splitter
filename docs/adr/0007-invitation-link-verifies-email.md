# Following an Invitation link counts as verifying its email

This amends ADR 0005. A Pending Member is emailed an Invitation: a one-time link carrying a random token, stored only as a hash, tied to that Pending Member, its Group and the email it was sent to, and working for 7 days. Signing up through the link creates the User for that email (the form shows it locked, and the server takes it from the token, never from the request), marks the email verified, and claims every Pending Member with it, exactly as verifying from the sign-up email does; a signed-in User whose email matches the token gets the same. ADR 0005's guarantee still holds, because receiving the token proves control of the inbox just as receiving a verification link does: only someone who can read that email can claim its Pending Members, and a forwarded link can't claim anything for a different email. A token stops working once used, once a newer Invitation is issued to the same Pending Member, and once that Pending Member is removed or claimed.

We chose this over making invited people follow a second verification email after signing up, which proves nothing the Invitation link didn't and leaves them on the dashboard instead of in the Group they were invited to. We rejected a Better Auth plugin or hosted invite flow because claiming is already a plain join in our own Postgres (ADR 0005), and we keep the token in our own table rather than Better Auth's `verification` table so it can name the Pending Member and Group it belongs to.
